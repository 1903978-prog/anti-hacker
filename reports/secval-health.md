# secval health report (2026-10-18)

App: secval.onrender.com. Rated from the code (1903978-prog/anti-hacker, integration, commit d7d109c) and what was checked in this thread. Everything here is an **estimate**, and anything not checked is marked "not verified".

| Area | Score | Why |
|---|---|---|
| Security & Access Control | ~90 | Checked in code and tests: every API call, reads included, needs the secret token (compared in constant time; refused if none is configured). The web page signs in once and gets an HttpOnly, Secure, SameSite=Strict cookie, and changes made with that cookie must come from secval's own page. Wrong tokens are capped at 10 a minute across all callers, while the right token always works. Plus a 120/min rate limit, strict headers and CSP, a fail-closed policy gate before every scan, an append-only audit trail and a kill switch. Held back: one owner token rather than named accounts with two-step login. |
| Data Protection & Privacy | ~95 | Scored 19/10/2026 on the 10-rule checklist (reports/privacy-checklist.md): data map 10 and outside services 10 (docs/database.md lists the alert address, in-memory IP, audit actor, Resend, Backblaze B2 and Render with their data terms, `c2aef9b`), no real data in code 10, history 10, locked away 10 (HttpOnly Secure SameSite=Strict cookie, no-store), encrypted 5 (HSTS on, but the Litestream copy on B2 has no encryption of its own), clean-up 10 (no third-party personal data; backups 3 days), rights 10 and public notice 10 (owner-only app), logs 10. |
| Data Integrity & Consistency | ~88 | Updated 26/10/2026 (E, not verified live until shipped): input is validated (zod), multi-row writes use transactions, database triggers block edits to the audit log, and numbered schema migrations are recorded and tested (test/migrations.test.ts). New: at start and once a day the store is checked for corruption, broken links between records, missing migrations and missing audit-log guards (test/integrity.test.ts); the result shows on /health, and /health/store answers 503 when something is wrong. Held back: app names are text with no link to the allowlist, and some counts are stored twice. |
| Data Persistence & Recovery | ~82 | Updated 26/10/2026 (E): the daily store check now also runs on the live data. Litestream copies the store to Backblaze B2 about every second and restores it when Render starts a fresh machine. Restore is proven: ownership proofs for compplan, lm-op-model and nexus survived the 18/10 redeploy (Livio's screenshots). Built in code: a daily restore test copies the backup into a scratch file and checks it is intact, with the result and a "Test restore now" button under Settings and in the audit trail; 3 days of history are kept (cut from 7 on 20/10/2026 to stay inside the free Backblaze daily list-call cap); a failed restore at start is shown as a warning instead of passing silently. Held back: one backup location only, the last second of changes can be lost on a sudden wipe, and the daily test is not yet seen passing live. |
| Database Design & Structure | 90 | 1 One master database: 10/10 (one SQLite file; the Backblaze copy is only a backup); 2 No duplicated data: 5/10 (each changed report is stored again in full, findings_count repeats a count of findings, host is copied onto every score row); 3 Links between records: 5/10 (findings link to scans and scores to reports with enforced foreign keys, but scans, uptime checks and reports name the app as text with no link to the allowlist); 4 Unique IDs and rules: 10/10 (every table has a primary key and not-null rules; database triggers now reject bad scan mode, scan status, severity, a score outside 0-100 and bad uptime values, server/migrations.ts); 5 Versioned schema changes: 10/10 (numbered migrations in server/migrations.ts, run once each on start and recorded in schema_migrations; tested on an old database copy in test/migrations.test.ts); 6 Backups and proven restores: 10/10 (Litestream streams to Backblaze B2; proofs survived the 18/10 redeploy per Livio's screenshots); 7 Indexes on main lookups: 10/10 (9 indexes cover every lookup: findings by scan, scans by target, scores, facts and reports by app); 8 Sensitive data protected: 10/10 (no passwords stored, the token lives in settings, scans keep findings not site data); 9 No secrets in code: 10/10 (database path and backup keys come from environment settings, litestream.yml); 10 Clear naming and documented schema: 10/10 (one snake_case style; every table, link, rule and index written down in docs/database.md) |
