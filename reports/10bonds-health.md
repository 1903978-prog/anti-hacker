- **Database:** one Neon Postgres project: table `public_bonds` (read-only login `tenbonds_reader`, filled daily by lm-op-model) and schema `app` for accounts and site data (login `tenbonds_app`).
- **GitHub:** repo `1903978-prog/10bonds` (public), branch `main`; pushing to `main` runs all checks, then deploys.

2. **Never-confirmed accounts are kept indefinitely** (a cleanup rule would need Livio's OK, since it deletes accounts).
3. **One machine:** a second Fly machine would remove the last single point of failure but costs money (not proposed).
