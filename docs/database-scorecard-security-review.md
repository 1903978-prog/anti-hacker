# Security review: database scorecard (PR #45), revision 2, 05 Nov 2026

Reviewer: the build session plus tests. This is NOT an independent penetration test.

| Risk | Control | Evidence |
|---|---|---|
| Secval writes to a monitored DB | Login has no write/DDL/owner/admin right, checked from the database's own `has_*_privilege` before every scan; failure refuses the scan and raises a P0 alert. Session is `READ ONLY` with local timeouts; role default is read-only; every statement passes a SELECT-only guard. | Real Postgres tests: DELETE/CREATE refused for the role; INSERT-granted, blanket-SELECT, secret-column, other-schema and PUBLIC-granted logins each detected and the scan refused. |
| Over-broad read access (tenant/personal data) | No table-wide SELECT; column-level grants limited to key columns the checks compare, generated by secval for the owner to review; secret-looking names never auto-granted; no other schema; no default privileges for future tables. | Real Postgres: after step 2 only the listed columns are readable; `SELECT name FROM clients` and `SELECT amount FROM invoices` fail with permission denied. |
| Credentials leak | Strings only in env vars; never returned by any API or log; errors reduced to fixed labels; the preflight prints no secrets. | Tests assert the password never appears in any response. |
| Plaintext connection | Remote host without `sslmode=require` refused; certificate verified. | Unit tests; connectivity stage. |
| SQL injection | No user input reaches SQL; identifiers come from the catalog, regex-checked and quoted. | `ident()` in `readonly.ts`; grant generator uses it. |
| Runaway load | Statement timeout 10 s, lock timeout 2 s, check budgets, table-size cap, total time cap (60 s quick / 300 s deep), one scan per app, 60 s dedupe, each check in a SAVEPOINT so one refusal cannot abort the rest. | Tests: budget, dedupe, time-budget skip. |
| Unauthorized use of the tab | Same token/cookie auth as the rest of secval; attestations are time-bound and append-only. | HTTP tests (401). |
| E-mail alerts | None sent by this module. | Code review. |

Residual risks:
1. A compromise of the secval server or Render account exposes read access to the granted key columns only (IDs), not whole tables. Rotate with `ALTER ROLE secval_monitor PASSWORD '...'`.
2. The grant script is reviewed by a human; a wrong approval could add columns. The permission check still blocks secret-looking names and table-wide reads.
3. TLS reporting from `pg_stat_ssl` can read "unknown" through a pooler; the client-side TLS requirement is the real control.
4. Not yet run against the real Neon databases or from Render.

## Rollback

- Delete the three `SECVAL_DBARCH_URL_*` variables on Render (one restart): the tab shows N/V and nothing connects.
- Per database: `DROP OWNED BY secval_monitor; DROP ROLE secval_monitor;` in the Neon SQL Editor.
- Code: revert PR #45. Migration 5 only added four inert tables.
